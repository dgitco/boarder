# 노드 규칙 묶음 — 노드 하나 = 목표 하나

이미 쓰는 하네스(tmux · Herdr · 여러 Claude Code / Codex 창)가 있는 사람이 자기 총괄(메인) 에이전트에게 그대로 붙여 넣는 규칙이에요.
요청이 올 때마다 창(노드)이 새로 생겨 「노드인 이유가 없어지는」 일을 막아요. Boarder 기본 하네스는 처음부터 이 규칙으로 돌아요(감독 규칙 「목표 하나」, 기본 켬).

## 붙여 넣을 글

```text
[노드 규칙 — 노드 하나 = 목표 하나]
1. 작업 창(노드) 하나는 요청 하나가 아니라 목표 하나다. 같은 목표 = 같은 제품 · 같은 영역의 개선 · 다듬기 · 「누르면 바로 반영」 · 입력칸 고치기 · 버그 · 후속 요청.
2. 새 요청이 오면 먼저 지금 노드(열림 · 쉬는 중 · 닫힌 지 며칠 안 된 것) 목록을 보고, 목표가 같은 노드가 있으면 그 노드에 넣는다 — 그 노드 할 일 목록의 한 줄로.
   쉬거나 닫힌 노드면 다시 열고 넣는다. 새 노드는 목표가 다를 때만 연다: 다른 제품 · 다른 영역(회사) · 따로 오래 가는 목표.
3. 한 노드에 일이 쌓이면 노드를 쪼개지 않는다. 그 노드가 한 줄씩 차례로 하거나, 나눌 게 있으면 그 노드 안에서 나눈다 —
   서브에이전트, 또는 같은 창 오른쪽 판에 도우미(프론트 · 백엔드처럼 같은 파일을 안 건드리게, 겹치면 git worktree).
4. 일을 다른 노드에 넘길 때도 같다: 목표가 같은 노드가 있으면 거기로, 없을 때만 새 노드.
5. 같은 목표 노드가 둘 이상 생겼으면 하나로 합친다: 남는 노드 할 일 목록에 다른 노드의 남은 줄을 옮기고, 기다리던 것(답 · 감시 · 카드)도 남는 노드로 옮긴 뒤 다른 노드는 닫는다. 끝난 노드는 닫는다.
6. 노드 이름은 처음 보는 사람도 아는 쉬운 말 목표로 짓는다(오류 코드 · 기능 번호 · PR 번호 · 영문 코드명 없이).
```

## 왜

- 요청마다 노드를 열면 보드가 요청 목록이 되고, 같은 제품 일이 여러 창에 흩어져 서로 같은 파일을 고치고, 앞 요청의 맥락을 다음 창이 모른다.
- 목표 하나에 노드 하나면 그 노드가 맥락을 쥐고 차례로 처리하고, 무거우면 안에서 도우미 · 서브에이전트로 나눠 빨리 끝낸다.

## Boarder 에서

- 감독 규칙 「목표 하나」(기본 켬): 메인 봇이 역할을 새로 만들기 전에 같은 목표 역할이 있는지 보고, 있으면 그 역할 채널로 안내해요. 같은 이름 역할 창이 있으면 새 초안을 받지 않아요.
- 역할 창은 같은 목표의 다른 요청을 그 창에서 받고, 나눌 게 있으면 그 안에서 나눠요. 일을 끝낸 역할 창은 닫지 않고 쉬다가, 그 역할 채널에 글이 오면 다시 열려요.
