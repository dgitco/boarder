# 보더 웹 화면 일 규칙

운영에서 같은 정정이 여러 번 나온 것만 적는다(2026-11-05). 화면을 바꾸기 전에 읽는다.

- **범위는 요청만큼.** 요청한 화면 · 동작만 최소로 바꾼다. 화면 구조를 새로 짜거나 요청마다 새 노드 · 새 화면을 만드는 큰 변경은 먼저 시안으로 확인받는다. 보더는 사람마다 쓰는 법이 달라서, 한 사람 쓰임에 맞춰 막는 제한을 넣지 않는다(설정 값으로).
- **레퍼런스는 뜻부터.** 레퍼런스(스크린샷 · 링크)를 받으면 무엇을 보라는 것인지(배치 · 간격 · 흐름 · 문구)를 먼저 적고 원본과 대조한다. 그리기 전에 시안을 보인다 — 레퍼런스 화면을 그대로 옮겨 넣지 않는다.
- **여백 · 정렬은 한 기준.** 같은 줄 · 같은 열은 한 패딩 기준을 쓴다. 기능 없는 요소와 어중간한 위치(선에 안 맞는 메뉴 · 아이콘)는 넣지 않는다. 캔버스 · 화면 캡처는 겹침 · 정렬 검사 도구가 있으면 그것으로 잰 뒤 눈으로 본다.
- **기존 컴포넌트를 그대로.** 입력칸 · 결정 카드 · 헤더 · 메뉴는 운영에 있는 컴포넌트(`src/components/ui` 와 이미 쓰는 화면 조각)를 재사용한다. 비슷한 것을 새로 만들거나 갈아엎지 않는다 — 다르게 보이면 그 컴포넌트를 고친다.
- **보내기 · 고르기 · 지우기는 낙관적 갱신 한 길.** 누르면 화면이 바로 바뀌고(낙관적 갱신), 실패하면 되돌리고 알린다. 같은 데이터는 한 곳에서만 그린다 — 두 곳에서 그리면 깜빡임(빈 선 → 내용)과 낡은 표시가 생긴다.
- **오류는 제자리 토스트 + 원인 기록.** 클라이언트 오류는 화면을 깨지 않고 그 자리 토스트로 짧게 보이고(「일시적인 오류」만 되풀이하지 않음), 원인(요청 · 응답 코드 · 메시지)을 기록에 남겨 다시 볼 수 있게 한다.
